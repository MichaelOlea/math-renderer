# Notes for AI agents

## Adding or changing a lesson

Follow `skills/math-renderer-lesson/SKILL.md`. The workflow: transcribe the teacher's problem, solve and verify it, write the solution as Markdown, revise with the teacher until they explicitly approve, then write the lesson data. Never write lesson data before that approval.

## Themes and backgrounds

Teachers can ask for a look that fits their class or the season, such as the animated autumn valley in `examples/`. Follow `skills/math-renderer-theme/SKILL.md`: work on a copy, change only styles and decorative scenery, keep the math readable, and test the copy with `MATH_PAGE=<copy> npm test`.

## How the project is laid out

- `math-rendere.html` is the whole product: one self-contained file that works offline. Keep it a single file; do not split it or add a build step for viewing it.
  - `<script id="lesson-data">`: `LESSONS`, `TEACHING_TIPS`, `KEY_STEPS`. The only part a lesson change touches.
  - `<script id="lesson-artwork">` and the `#glyphDefs` sprite: generated by `npm run artwork`. Never edit by hand.
  - `<script id="engine">` and the styles: the renderer.
- `tools/build-artwork.js`: regenerates the equation artwork from the TeX in `LESSONS`.
- `tests/`: Playwright tests for layout (fit, alignment, readability) and controls, at eight screen sizes.

## Before finishing any change

```
npm run artwork   # only if any TeX changed
npm test          # checks the artwork is current, then runs every test
```

`npm test` must pass. Use `npx playwright show-report` to see screenshots of failures. Fix layout problems in the lesson's `stack` / `mobileStack` fields or in the styles, never by changing the mathematics.
